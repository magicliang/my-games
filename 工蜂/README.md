# 兵蜂 FC

以 1986 年 FC 初代《兵蜂》为目标的浏览器游戏。当前重点是玩法机制，采用 512×480 正交俯视画面，角色、场景与音效由代码绘制/合成。无需安装依赖，双击 `index.html` 即可运行。

也可在本目录运行 `python3 -m http.server 4173 --bind 127.0.0.1`，打开 <http://127.0.0.1:4173>。

## 操作与设置

| 动作 | 单人 / 1P | 双人时 2P |
| --- | --- | --- |
| 移动 | WASD；单人也可用方向键 | 方向键 |
| 射击 | 空格，可改键 | 逗号 `,` |
| 对地投弹 | F，可改键；前方有锁定目标才发射 | 句号 `.` |
| 暂停 / 继续 | P / Esc | 共用 |
| 糖果附加技巧 | 按住 Shift 拾糖果获得横向三向弹 | 糖果仅单人 |

画面下方“血量与按键”可在开局前或游戏中调整：

- **经典**：中弹失去双臂，无臂再中弹或撞敌损失一架。
- **高血量**：每架 2–99 血，默认 10。敌弹扣 1、碰撞扣 2；装甲耗尽损失一架，下一架恢复满甲。应用模式会补满装甲。
- **无敌**：敌弹与碰撞不损血、不丢手臂、不消耗护盾。仍可射击、投弹、收集与通关。
- 点击“射击”或“投弹”设置按钮，再按新键；Esc 取消。移动、暂停、2P 及已分配按键不能重复使用。改键保存在本机浏览器，模式每次重新打开默认经典。设置不复活已出局的玩家。

触屏有方向、射击和投弹按钮；也可在战场拖动移动。按钮使用动作名称，不再用容易与 WASD 混淆的 A/B 标记。

## 已接入的机制

铃铛共享追打计数、特殊颜色后一发回黄、黄铃连分及漏铃归零、过击蜂敌；地空攻击隔离、单发锁定投弹、固定地面奖励周期；永久三向弹、历史轨迹分身、屏障互斥；FC 双臂受伤、每命一次救护车、原地复活、独立得分与奖命；双人 Fire/Star 合体；五类 Boss、自动过关及保留装备/分数的后续周目。

## 复刻精度

规则与数值来源见 [MECHANICS.md](MECHANICS.md)。官方说明书确认的规则与实玩记录推定的数值分别列出。**这不是经过 ROM 输入回放验证的逐帧复刻**：地图坐标、敌群出现时刻、速度/碰撞盒、铃铛部分计数、Boss 武器相关耐久和高周目曲线仍需原版逐帧对照。目前关卡采用可复现的编队时间表；Boss 行为分别实现，不代表出场帧完全相同。

旧 `webgl-renderer.js` 暂时保留，但当前页面不加载它；3D 与可执行文件打包不属于本次机制修订。

## 验证

```sh
npm run check
```

检查 JavaScript 语法并运行核心规则及实际引擎测试，无第三方依赖。浏览器回归需要环境中已有 Playwright（未添加为项目依赖）：

```sh
# 先启动上面的本地静态服务器
TWINBEE_PLAYWRIGHT_PATH=/absolute/path/to/playwright TWINBEE_BROWSER_CHANNEL=chrome npm run test:browser
```

可用 `TWINBEE_URL` 改服务器地址，`TWINBEE_QA_DIR` 改截图/报告目录，默认 `/private/tmp/twinbee-fc-qa`。浏览器测试区分真实键盘/触屏操作与 `?debug=1` 中的确定性场景；普通页面只提供只读快照，不能跳关或改状态。
