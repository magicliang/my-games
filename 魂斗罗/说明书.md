# 魂斗罗：丛林突击 3D 说明书

本作以 FC 日版初代《魂斗罗》的横版第一关为玩法参考，采用原创 FC 风格像素人物，保留 Three.js 三维场景与渲染。玩家、敌人和子弹都在 X/Y 战斗平面中运动；深度只用于美术，不提供纵深绕行或鼠标瞄准。

原版规则依据见 [FC 原说明书与录像核验](./docs/FC_REFERENCE.md)。下文带数字的速度、间隔、槽位、血量和地形坐标是**本项目当前调校值**，尚未证明等于 FC ROM 常数。

## 启动与检查

在本目录执行：

```bash
npm install
npm run dev
```

打开终端给出的地址，默认 `http://127.0.0.1:5173/`。若端口已占用，以终端实际地址为准。可在 Codex 内置浏览器或支持 WebGL 的桌面/移动浏览器运行。

```bash
npm test
npm run check
npm run build
npm run preview
```

`build` 先做 TypeScript 类型检查，再生成 `dist/`；`preview` 只在本机预览构建结果。本轮不推送、部署或增加运行依赖。

## 操作

| 动作 | 默认键位 | 行为 |
| --- | --- | --- |
| 左右移动 | `A/D` 或 `←/→` | 地面松键停步；空中保留水平运动，按反方向可改向 |
| 方向瞄准 | `W/S` 或 `↑/↓` 与左右组合 | 上射、斜射；空中可向下射击；松开方向按当前朝向水平射击 |
| 伏地 / 潜水 | 地面 / 水中单独按 `S/↓` | 地面伏地可水平开火；潜水时不能射击，并避开普通敌弹/接触伤害 |
| 跳跃 / 下落 | `K`、`空格` 或 `X` | 跳上平台；在单向平台上按 `下 + 跳` 穿到下层；水中不能跳 |
| 射击 | `J` 或 `Z` | 普通枪、F、S、L 每按一次射击一次；M 可按住连续射击 |
| 暂停 / 继续 | `Esc` 或屏幕按钮 | 暂停时冻结游戏计时；恢复不补算离开期间的时间 |
| 重新开始 | 暂停页“从头重新开始”或结算页“重新出击” | 重置敌人、桥、道具、分数和镜头，沿用本次模式 |

鼠标只操作界面按钮，不开枪、不选择射击目标。方向键和跳跃/射击可同时操作，无需数字小键盘。

“操作与设置”中点击动作后按新键；该动作原有别名会被替换，冲突的键位不会保存。点击“恢复默认键位”恢复上表。键位在当前浏览器本地保存；浏览器拒绝存储时，本次会话内仍可使用。

触屏设备自动显示八方向、跳跃、射击按钮，可多指同时移动、射击和跳跃。普通枪/F/S/L 点按火键，M 按住火键。桌面也可在设置中勾选“显示触屏按键”。切走窗口、标签页隐藏或触点取消时会释放输入；窗口失焦会自动暂停，返回后需主动继续。

## 人物画面

人物使用原创像素图集：红头带、赤膊、蓝色军裤为玩家，橄榄绿制服为敌兵。站立、六帧跑步、四帧空中翻滚、伏地、游泳、潜水与阵亡分别绘制；持枪随方向变化。Three.js 使用最近邻采样，不平滑放大像素；有限图集和材质由所有人物复用。人物脚底、枪口与原有战斗坐标对齐，人物改图不会增大碰撞体或改变跳跃距离。

## 模式、受击与复活

| 选项 | 本作行为 |
| --- | --- |
| 经典（默认） | 初始 3 条命，每条命 1 点体力；有效受击即损失一命 |
| 高血量（辅助） | 初始 3 条命，每条命 5 点体力；普通受击扣 1 点，体力耗尽才阵亡；落坑仍阵亡 |
| 无敌（辅助，默认关闭） | 忽略普通敌弹和敌军接触伤害；落坑会触发屏内安全救援且不扣命，救援仍重置武器 |

辅助模式在画面左上持续标记，不能误认为经典模式通关。标题页输入 `↑ ↑ ↓ ↓ ← → ← → B A Enter` 后点击开始可获得 30 条命；开局提示与 HUD 会持续明确标记“30命”辅助，损失生命后仍保留该标记。普通重新开始恢复为 3 条命，并清除该辅助标记。

受击时有短暂、低强度的颜色/亮度提示；画面显示最近一次受击原因，例如“敌弹命中”“与跑兵接触”“堡垒抛射弹命中”或“坠入断崖”。系统开启减少动态效果时，以静态边缘提示代替亮度变化。

阵亡后约 0.7 秒进入复活流程：在当前屏内找到安全地表，从上方落回战斗平面，并有 2 秒保护；镜头不倒退到旧检查点。复活恢复体力、普通枪，清除 R 强化。高血量模式的非致命受击有 0.8 秒保护。初次开局有 1.5 秒保护。暂停会保留所有这些游戏保护时间。

## 武器与补给

先射击飞行胶囊或固定武器箱，再接住弹出的道具；不是直接碰触未击破的箱子取得装备。本作容器需要 2 次命中，道具弹出后下落，可落在平台或河面。

| 武器 | 输入与弹道 | 最短射击间隔 | 弹速（单位/秒） | 同时在场弹额 |
| --- | --- | --- | --- | --- |
| 普通枪 | 按次射击，直线弹 | 0.13 秒 | 22 | 4 |
| M 机枪 | 按住连射，直线弹 | 0.10 秒 | 26 | 6 |
| F 火球 | 按次射击，沿前进方向叠加圆周旋转 | 0.20 秒 | 18 | 4 |
| S 散弹 | 按次发射五枚扇形弹，位于同一战斗平面 | 0.18 秒 | 23 | 10（两组五发） |
| L 激光 | 按次发出五段贯穿光束，再次射击取消旧束 | 0.13 秒 | 30 | 5 段（同一束） |

表格来自 `src/game/combat.ts` 的 `WEAPON_RULES`。弹额已满时不会产生新弹；S 不足五个空位时不发射不完整的一组。切换武器不会立即清除所有已经飞出的普通弹，原有弹也计入总弹额；再次发射 L 会清除旧玩家弹并发出新束。命中或离开可用画面范围会释放相应槽位。

S 相邻弹角间隔为 0.16 弧度；F 当前在前进和垂直方向叠加半径 0.48 单位、角频率 20 的圆周轨迹；L 段距为 0.4 单位，每段对同一敌人最多命中一次，每次伤害为 1。这些是本作行为，原版散弹槽位分配、火球旋转、激光分段和伤害仍待逐帧校准。

`R` 是弹速强化，不占用独立枪械槽：普通枪/M/F/S 弹速乘 1.5，射击冷却和弹额不变。R 不能与 L 同时生效；取得 L 会清除 R，持 L 取得 R 不生效。当前实现换到其他非 L 枪时保留 R；该跨武器保留规则仍需原版受控测试。

本关还放置一个 `B` 防护道具，当前保护 15 秒游戏时间。B 的具体出现位置和时长属于本作编排，不作为原版第一关配置的结论。死亡清除武器强化，重新开始重置所有补给。

## 第一关路线与战斗

丛林起点 → 第一座桥/河水 → 多层高台与火力点 → 第二座桥/河水 → 东岸平台与炮台 → 断崖 → 堡垒。

桥按段顺序坍塌：踏入桥前附近后 0.8 秒开始，每隔 0.25 秒破坏一段；渲染桥段和承重面一起消失。爆破效果本身不扣命，失去桥面会落水。落水后左右游向岸边，遇到岸沿自动上岸；不能靠按跳跃离开水面。

后段断崖与河水不同。当前断崖位于 **X=121–125，宽 4 单位**，需要提前起跳；落到画面下方会阵亡（无敌辅助触发救援）。本作跑速 5.4 单位/秒、跳跃初速 12、重力 24；模拟固定为每秒 60 步，连续运动参数不等同于 FC 像素/帧。

普通跑兵从边缘和预设敌群进入，不射击，接触有危险；射手和炮台发射可见敌弹；堡垒双炮发射抛物线炮弹。敌人到达可用视野时才激活，不能通过移动到纵深躲开。

平台是单向承重面：向上可以穿过，下降经过平台高度才落地；不会站在平台下方就瞬移到顶面。平台和桥的视觉几何依据相同地形数据生成。

镜头只向右推进，跳跃和后退不会带动镜头上下或回滚；到堡垒区域锁定。攻击堡垒底部红色核心即可通关，**不要求先拆掉屋顶射手和两门炮**；先清除火力点是一种安全打法。核心当前为 32 点生命。生命耗尽出现失败结算，两种结算都可重新开始。

## 验证范围与剩余校准

自动测试覆盖实际运行时中的跳跃/平台、水中/桥梁、武器命中、死亡复活、暂停计时、失焦释放、Boss 击破和重新开始；输入测试包含键盘别名、冲突改键和多触点取消。测试脚本及执行记录位于 `tests/` 与 `docs/`，浏览器验证以本轮实际生成的证据为准，不能把纯规则单测当作整关操作通过。

尚待原版逐帧测定的项目包括运动轨迹/枪口坐标、武器冷却/弹额/弹速、R 换枪规则、L 分段伤害、无敌帧、敌人生成与开闭炮台时序、第一关精确地形和补给坐标。现有像素人物、三维场景、比例、难度和敌群编排属于本项目，不声称逐像素或逐帧复刻；本轮不扩展至其余七关。
